# AltScreenSearchIndex actual-source oracle

## Scope and authority

This slice ports `pi/packages/tui/src/alt-screen-search.ts:1–196`: corpus construction, query normalization, literal `/giu` search, UTF-16 offset/cell projection, the source/query cache, mutable result identity, and match keys. It does **not** execute Search UI, native `TuiAltScreen` lifecycle or the full native alt-screen suite.

`run.mjs` copies 22 complete, hash-recorded upstream modules to Rust `target/alt-screen-search-oracle`, never rewrites the read-only sibling checkout, and runs the actual exported functions/class. Internal corpus/source/query observation reads TypeScript-private fields after actual execution; it does not implement those fields in the oracle. The referenced `tui-alt-screen.test.ts` hash is provenance, **not proof that the native suite ran**. Full native suite still needs unavailable offline `@xterm/headless`.

The offline dependency is the existing `get-east-asian-width@1.6.0` snapshot in workspace `.migration-handoff/reference-deps`. Runtime is pinned by the manifest: Node25.8.2 / Unicode17.0 / ICU78.2 / V8 14.1.146.11-node.24. Do not silently refresh expected data on a different runtime.

## Runtime implementation is not fixture injection

The Rust index constructs its own corpus, strips terminal sequences in original UTF16 units, uses its own `unicode-segmentation1.13.3` (Unicode17) and existing width implementation, and projects its own KMP literal matches back into source spans. Oracle `graphemes` and expected corpus/results are **not supplied to the runtime**.

A mapped U+FFFD segmentation view is used only for finding grapheme boundaries of ill-formed UTF16. Original units remain stored, compared, measured and matched; a lone surrogate is not converted into a searchable/printed replacement character. The 766 actual-Intl/conformance cases plus contextual raw-unit cases are empirical coverage, not a claim of full `Intl.Segmenter` API/locale/word-segmentation equivalence.

Installed regex-syntax0.8.11 uses Unicode16 tables. Rather than silently using them, the new matcher has a general Unicode17 C/S simple-fold table generated by `docs/migration/tools/generate_search_case_folding.py`. It is **not derived from search expected outputs** and excludes full/Turkic mappings. UTF16 token offsets are retained separately, and lone surrogates cannot match inside valid surrogate pairs. Matching is non-overlapping and literal, with no Unicode normalization or multi-character full fold.

Standard source data and the Unicode license were explicitly acquired by read-only HTTPS on2026-09-24; URLs, hashes and exact provenance are in `unicode/acquisition.json` and `2026-09-24-225033-alt-screen-search-unicode-acquisition.log`. Do not describe the entire work session as network-free. All tests, oracle generation and table regeneration use the pinned local files and are offline; no package/library dependency was downloaded or changed.

## Ownership boundary

`SearchMatches`, `SearchMatchHandle`, `SearchSegments` and `SearchSegmentHandle` are distinct `Rc<RefCell<_>>` identities. Cache hits alias the same result array; recomputation replaces it while old arrays/matches/segment-array/segment aliases remain live. The oracle records weak-map object IDs; Rust test observation retains all observed allocations to prevent pointer reuse from masquerading as identity. The runtime never relies on those observer IDs.

This API is same-thread, typed dense arrays and representable nonnegative cell counts. It does not promise arbitrary JavaScript numbers, sparse/named array properties, getters or cyclic objects. External mutable borrows must be released before conflicting access; no `Send`/`Sync` or self-reentrant host guarantee is made.
